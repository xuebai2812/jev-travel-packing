# Jev · 旅行打包与交互 Demo

本仓库保存本地项目的完整代码，其中「带什么」旅行打包网站支持输入目的地和时长，用 Jev 选择物品，再通过 Matter.js 动画把 emoji 吸起。

## 代码结构

- `travel/`：本地旅行页面、物品目录、物理动画和清单交互。
- `packing.mjs`：Jev 旅行物品筛选逻辑。
- `travel-site/`：已发布旅行网站的独立版本，包含前端、Cloudflare Worker 接口、构建和验证脚本。
- `server.mjs`、`game.mjs`、`dist/index.html`：共用的本地服务与原有对话 Demo。这里的 `dist/index.html` 是直接使用的单页源码。
- `test-*.mjs`、`docs/`：测试、设计文档和实现记录。

## 从 GitHub 下载后运行

```sh
npm ci
cp .env.example .env
```

在 `.env` 中填入自己的 `TYPESAFE_API_KEY`，然后运行 `npm start`。
旅行页面地址为 `http://127.0.0.1:4173/travel/`，运行 `npm test` 检查项目。

线上版本可在 `travel-site/` 内执行 `npm ci`、`npm test`、`npm run build`。
仓库不包含实际密钥；`.openai/hosting.json` 仅记录原站点身份，向其他账号部署时应建立自己的站点配置。

## 原有对话 Demo

微信聊天风格的单关卡 HTML Demo：你答应安排周末约会，却迟迟没有跟进。每轮先由 Jev 给提示，你可以修改后发送，再由 Jev 判定这句话的效果。

## 打开

```sh
npm start
```

访问 http://127.0.0.1:4173 。需要 Node.js 20 或以上。本地服务器从 `.env` 读取 `TYPESAFE_API_KEY`；已有 key 时默认启用实时 Jev。

也可以双击 `dist/index.html` 离线体验。离线提示、角色回应和评分使用明确标注的示例规则，不调用模型。页面右侧（手机端点右上角星形图标）可切换实时模式；切换会重新开局。

## 玩法

- 只有一个场景：被忘记的周末约会。初始原谅值 20，最多回复 10 次。
- Jev 结合前文判断当前消息的可能含义，并从本轮参考措辞中选出建议，自动填入回复框。
- 发送实际回复后，Jev 判断其相对于前文带来的变化：伤害 -20、推卸 -10、重复或无进展 0、共情 +10、承担责任 +15、新的具体行动 +25。分数限制在 0–100。
- 达到 100 通关；归零，或 10 轮结束仍未到 100，则失败。同一轮达到 100 优先算通关。
- 每轮显示加扣分原因和对应角色反应，可以回看此前的提示，也可以重开一局。
- 请求失败不会消耗回合或修改分数；提示失败可重试，评分失败可保留原回复重新发送。

## Jev 与角色剧情

实时模式的 `POST /api/game/hint` 和 `POST /api/game/reply` 各调用一次 TypeSafe 官方接口 `https://api.typesafe.ai/v1/systemone`，使用 `jev-latest`，会产生 API 用量。请求包含本局对话、分数及回合。API key 仅由服务器读取。

Jev 做结构化 Choice 判断，不生成自由文本。提示措辞来自结合对话主题整理的候选池；对方的回应来自按判定效果、分数和前文选择的剧情分支。原谅值是本 Demo 的游戏规则，不是情绪测量；概率只是模型对几种解释的分布。

玩法参考 [哄哄模拟器](https://hong.greatdk.com/) 与[作者复盘](https://greatdk.com/1962.html)。这是独立的本地原型，没有连接原版服务或真实微信，不会给任何联系人发消息。聊天只保存在当前页面内存，刷新即重置。API 采用无状态请求，适合本地体验，没有排行榜或防作弊机制。

本地服务仅监听回环地址，不公开 `.env`、源文件或目录浏览。运行 `npm test` 检查输入验证、评分规则、分支选择、接口错误和既有功能；测试使用假上游，不消耗真实 Jev 用量。原有 `/api/analyze` 保持兼容。

## 带什么 · 旅行打包

已发布：https://pack-for-your-next-trip.sand-ai-1216.chatgpt.site （目前仅站点所有者可访问）。发布版的独立源码在 `travel-site/`，其 `.openai/hosting.json` 保存站点身份；后续发布沿用该站点。它只包含旅行页面和旅行 API，Jev key 由 Sites 的服务端 secret 管理。

新增旅行打包页面，与原有对话 Demo 共用本地服务：启动后访问 `http://127.0.0.1:4173/travel/`。如果使用其他端口，在地址中相应替换；例如 `PORT=4180 npm start`。

- 输入目的地和时长，例如「去冰岛 7 天，想自驾追极光」，停顿 850ms 后自动查询，回车立即查询。
- 使用已有的服务端 Jev key，真实筛选 56 件旅行物品，最多浮起 24 件；没有 key 或调用失败会说明原因，不展示伪造的模型结果。
- 点选物品可以手动增减，拖拽可以移动物品，清空行程后物品重新落下。
- 修改非空行程时保留当前物品，等新结果回来后再切换；查询失败也保留当前清单。上浮使用 Matter.js 弹簧吸引力，保留旋转、惯性与物品堆碰撞，并遵循系统的减少动态效果设置。
- 「我的行李」提供勾选和复制清单；页面刷新后打包状态重置。
- 未写月份时按当前月份的一般季节考虑，页面会显示这一假设；不接入实时天气。

首次运行需 `npm install`，新增依赖仅 Matter.js 0.20。`npm test` 同时检查原有 API、旅行 API、输入切换和真实 Matter 物理模拟。前端与物品目录在 `travel/`，模型问题及结果校验在 `packing.mjs`。API key 仍只由服务器读取。
